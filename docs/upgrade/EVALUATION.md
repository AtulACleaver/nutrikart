## 2. Recommendation Integrity & Constraint Adherence

### 2.1 Health Condition Rule Compliance

The recommendation engine strictly enforces health constraint thresholds prior to scoring and ranking. The benchmark requirement is **zero tolerance (0.0% error rate)** for limit violations in recommended baskets.

### 2.2 Unknown & Null Data Policy Compliance

* **Mandatory Nutrients**: Any product record with missing (`None`) or non-convertible nutrient values required by an active health filter must be disqualified (`passes = False`).
* **Preservation of Raw Values**: In the final recommendation JSON payload, fields where data is unknown must remain `null` rather than falsified to `0.0` or synthetic medians.
* **Benchmark Target**: 100% adherence verified across automated test suites (`test_filter.py`, `test_allocation.py`, `test_regressions.py`).

## 3. Mathematical Optimization & Allocation Quality

### 3.1 Linear Programming (PuLP / CBC Solver) vs Greedy Fallback

The optimization engine formulates budget allocation as a Bounded Knapsack Problem solved via Integer Linear Programming (CBC Solver):

$$\max \sum_{i \in P} (S_i + \delta) \cdot q_i \quad \text{subject to} \quad \sum_{i \in P} p_i \cdot q_i \le B, \quad 0 \le q_i \le Q_{\max}, \quad q_i \in \mathbb{Z}_{\ge 0}$$

Where:
* $S_i$: Raw nutrition composite score.
* $\delta = |\min_k S_k| + 1.0$: Positive translation factor preventing negative objective cancellation.
* $p_i$: Unit price (INR ₹).
* $q_i$: Integer quantity allocated.
* $B$: User budget (INR ₹).
* $Q_{\max}$: Per-product quantity bound (default: `household_size`).

### 3.2 Key Performance Indicators (KPIs)

1. **Budget Utilization**:
   $$\text{Utilization Rate} = \frac{\sum p_i \cdot q_i}{B}$$
   * **Target**: $\ge 90\%$ utilization when $B \ge \min(p) \times \text{household\_size}$.
2. **Integer Quantity Guarantee**:
   * All product quantities $q_i$ must be strictly non-negative integers ($q_i \in \{0, 1, 2, \dots\}$).
3. **Graceful Fallback**:
   * If CBC solver is unavailable or fails to reach optimality within 500ms, the system seamlessly falls back to greedy heuristic ranking with $100\%$ uptime and logs diagnostic status.

## 5. Explainability Verification

Every product recommendation generated by the engine includes a verifiable, deterministic explanation string in `selection_reason`:
* **Plain English backed by numbers**: e.g., `"Selected: low sugar (1.0g sugar vs 5.0g limit), high fiber (3.5g fiber), protein (6.0g protein) [score: +15.2]."`.
* **Zero Vague LLM Prose**: Explanations are directly computed from verified nutrient attributes and profile parameters.
* **Exclusion Transparency**: Candidates rejected during filtering or budget exhaustion are detailed in the `exclusions` response block with exact violating numbers.
